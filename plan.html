0. Application Features Plan & Endpoints

The complete functional design specifications mapping out all user-facing, provider-facing, and system-level features across our phases:

1. User Account & Security Features (Auth Module)

  • Role-Based Registration: Registers accounts under dedicated CUSTOMER or PROVIDER roles.
  • Decoupled Profile Setup: Spring Events automatically initialize correct profile entities on registration.
  • Password Encryption: All raw passwords encrypted using BCrypt prior to database persistence.
  • Stateless Authentication (JWT): Generates secure, signed tokens upon successful login verification.
POST/home/auth/user/register Registers account & initializes profile database entry.
POST/home/auth/user/login Verifies credentials and returns a secure JWT token.

2. Customer Module

  • Profile Management: Update contact data, first name, last name, and contact details.
  • Saved Address Book: Support for saving multiple addresses (Home, Office) with a default flag toggle.
  • Browse Catalog: Fetch and view all active service categories supported by the platform.
  • Create Booking: Request service bookings, which are auto-classified and summarized by AI.
  • Job Tracking: Monitor past historical jobs and current active job lifecycle states.
PUT/home/customer/profile Updates customer profile details.
POST/home/customer/addresses Adds an address to the customer's saved address book.
GET/home/catalog/categories Retrieves active categories in the services catalog.
POST/home/customer/bookings Creates a service request with description summaries.
GET/home/customer/bookings Fetches historical booking requests created by the customer.

3. Provider Module

  • Shop Setup: Configure shop name, portfolio descriptions, and contact metadata.
  • Online Toggle: Toggle active availability status to appear or hide in job matching queues.
  • Register Skills: Choose categories (e.g. Electrical, Plumbing) they are qualified to perform.
  • Job Dispatch Feed: Read matching, unassigned requests nearby.
  • Accept Bookings: Claim unassigned service requests.
  • Status Progression: Progress jobs through: ON_THE_WAY, ARRIVED, COMPLETED.
PUT/home/provider/profile Updates shop info, availability, and contact data.
POST/home/provider/profile/skills Associates provider skills with service categories.
GET/home/provider/bookings/matching Fetches matching job requests currently in REQUESTED status.
POST/home/provider/bookings/{id}/accept Claims booking request and sets status to ACCEPTED.
PUT/home/provider/bookings/{id}/status Updates active job status through valid lifecycle transitions.

4. AI & Administrative Module (Phase 1)

  • AI Description Cleanups: Local Ollama model rewrites messy, typos-filled user texts into clean summaries.
  • AI Auto-Classification: Automatically assigns booking to a category based on the description text.
  • Offline Fallbacks: If local AI is offline, logs details and keeps original text, allowing standard booking.
  • Platform Catalog: Add/manage category database records via admin interface.
  • Platform Auditing: Logs administrator audits when critical actions are taken.
POST/home/admin/categories Creates a new service category in the database.
GET/home/admin/audit-logs Retrieves platform administrative logs.

1. Entry Point: Traffic Ingress & Routing

To handle high concurrent loads, traffic must be optimized at the network edge before it ever reaches the Spring Boot container instances:

DNS & CDN Caching

Use Cloudflare/AWS Route53 for intelligent Geo-routing. Static assets (images, web resources) are cached at Edge servers, offloading 70% of reads from the core application servers.

API Gateway (Spring Cloud Gateway)

Functions as the single entrypoint for client requests. Resolves routing, handles cross-cutting concerns like rate limiting (Token Bucket via Redis), and performs initial JWT token signature validation.

2. The Modular Monolithic Architecture

Our application is structured as a Modular Monolith inside a single Spring Boot deployable. Rather than running separated, distributed network servers, domains are strictly isolated by Java package layouts. Communication across modules is kept clean via decoupled Spring Application Events and isolated database schemas:

Auth

Auth & Security Module (com.home.auth)

Manages secure user registration, BCrypt password hashing, CustomUserDetailsService lookups, and JWT session token generation.

Users

Profile Management Module (com.home.customer / com.home.provider)

Manages user contact fields, customer saved address books, provider shop settings, and online availability toggles. Profile entities are initialized asynchronously on account creation via Decoupled Spring Events.

Bookings

Booking & Catalog Engine (com.home.booking / com.home.catalog)

Handles platform catalog definitions and coordinates matching provider skills. Executes booking status lifecycle updates and notifies profile modules asynchronously.

AI

Local AI Core (com.home.ai)

Integrates Spring AI with local Ollama containers to run Llama3 algorithms. Automatically improves spelling and classifies user booking category assignments based on text inputs.

3. Persistence & Caching Strategy

Database read/write locks are the single biggest bottleneck under peak loads. We implement a tiered caching and storage pattern to scale performance:

Redis Caching

Caches hot database resources (like active provider details, available categories) with a Time-To-Live (TTL) configuration. Reduces database load by up to 80%.

Read-Write Splits

Deploy a Primary PostgreSQL instance for all writes (booking transactions) and multiple Read Replicas. Java dynamically routes read queries to replicas using routing data sources.

Object Storage

Binary data (provider avatars, shop portfolio photos) are uploaded directly to MinIO/S3 and stored as metadata links in the database to prevent database bloat.

4. Asynchronous Processing & Kafka

To keep API responses fast, slow tasks (like notification dispatches, AI prompt summarization, location updates) are handled asynchronously using a message queue:

Kafka

Apache Kafka Messaging Cluster

Used as the distributed message bus. When a customer submits a booking, the booking service saves the record and publishes a `BookingCreated` event to a Kafka topic.

Worker

Asynchronous Consumers

* **AI Worker:** Consumes `BookingCreated` events, sends the description to Ollama, and updates the database with category tags and summary details. * **Notification Service:** Consumes event topics and sends email/SMS notifications to matched providers asynchronously.

6. Observability & Monitoring

With multiple microservice instances, locating errors becomes extremely complex. We configure the standard monitoring stack:

Centralized Logs (ELK)

Logback writes logs in JSON format. Filebeat collects and pushes them to Logstash/Elasticsearch for real-time indexing and search.

Metrics (Prometheus & Grafana)

Java microservices expose resource data via `/actuator/prometheus`. Prometheus pulls metrics, and Grafana maps memory/CPU usages on panels.

Traces (OpenTelemetry)

Distributed request tracing maps individual customer request paths across various microservice environments, displaying latency traces.

6. DevOps: Docker, CI/CD & Kubernetes

Each service is compiled and deployed as isolated containers in a local or cloud cluster managed by Kubernetes.

Multi-Stage Dockerfile Blueprint 

# Stage 1: Compile the Jar file
FROM maven:3.8.5-openjdk-17-slim AS builder
WORKDIR /app
COPY pom.xml .
COPY src ./src
RUN mvn clean package -DskipTests

# Stage 2: Create lightweight running container
FROM openjdk:17-jdk-slim
WORKDIR /app
COPY --from=builder /app/target/home-service-application.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
